# 退出码与失败处置细则

本文件是 `SKILL.md` §5 的展开。**数字退出码是稳定契约**，键名与自然语言提示不是——
能在退出码上分支就别去匹配错误文本。

> 文中的 `run` 就是 `SKILL.md` §1 解析出的调用形态；换了新 shell 要先重跑 §1 那个块。
## 全表

| 码 | `.error.kind` | 含义 | 处置 | 为什么这样规定 |
|----|---------------|------|------|----------------|
| 0 | — | 成功，**含 0 条结果** | 正常使用；空数组如实说"没查到" | 查无结果在服务端不是错误，重试只会白烧配额 |
| 2 | `USAGE` | 本地校验拦下：缺参、枚举非法、域名格式不对、范围越界、坏配置 | 改正后可再发**一次**；**零出网**，不消耗配额 | 这类失败根本没到服务端，重试成本为 0，但反复试同一个坏参数说明你没读 `--help` |
| 3 | `TRANSPORT` | TCP 不可达 / DNS 失败 / 连接被拒 / HTTP 5xx | 停止并回报"网关不可达"。**不要尝试隧道降级**、不要自己改端点（CLI 缺省 `auto` 会在这一格自己 spawn SSH 转发，这正是每条命令都要显式 `--tunnel off` 的原因，见下第 4 条） | 起隧道是维护者的共享基础设施动作，不属调用方权限；再发一次只是多烧一次往返 |
| 4 | `PROTOCOL` | `initialize` 失败、缺 session id、SSE 帧无法解析、JSON-RPC `error` 对象、schema 漂移 | 停止并回报；把"要不要跑 `doctor`"交回给人 | `doctor` 自带一次最小搜索，那次配额支出该由人决定 |
| 5 | `TOOL_ERROR` | `isError=true` 且不属于池死亡（上游报错、工具内部异常） | 停止并回报服务端原文，**绝不自动重试** | 实测：非池死亡的请求级错误也可能轮换打满服务端多个 Key，盲重试是真实的伤害 |
| 6 | `POOL_DEAD` | 服务端 Key 池进入 `ERROR` **终态** | **本会话内全部搜索立即停手**，回报"需运维介入" | 客户端无法自愈；继续灌请求只是白烧共享配额并把失败面摊宽 |
| 7 | `TIMEOUT` | 本地总超时（`search` 默认 45s，`crawl`/`map` 默认 120s） | 可**一次**加 `--timeout 90`；仍失败就回报 | 超时类永不自动重试——请求可能已在上游执行，重试等于 twice-spend |
| 8 | `RATE_LIMITED` | 上游 429 语义透传出来 | 退避 ≥5 秒后**至多一次** `--retries 1`；再失败就回报 | 429 有退避语义，服务端会冷却后换 Key，可能自行恢复——与 6 本质不同 |
| 130 | `INTERRUPTED` | 被 Ctrl-C 打断 | 回报被中断，不重发 | 不会留下半截 JSON |

## 失败信封长什么样

`--keys-en` 下（成功时 `error` 为 `null`）：

```json
{
  "ok": false,
  "tool": "tavily-search",
  "query": "示例",
  "results": [],
  "error": {
    "kind": "USAGE",
    "message": "--include-domain：include_domains 含非法域名 '!!bad'：必须是带合法后缀的纯域名（如 example.com）",
    "hint": "修正参数后重试；这类错误不会发出任何网络请求。"
  }
}
```

四条实测事实：

1. `results` 是**空数组**而非 `null`，消费方不必判空类型。
2. 失败时 `pages` / `failed` / `nodes` / `images` 也都在，全是空数组——**别遍历它们**，会误判成"命令返回了空网页"。
3. `hint` 是给人看的中文建议。退出码 6 的 `hint` 里含一条**服务端运维命令**：读它、转述给人，**不要执行**。
4. 退出码 3 的 `hint` 原文是"确认端点可达；必要时改走 SSH 隧道"（它点名了一个 CLI 旗标，本文刻意不复述）。
   **别照做**：`--quiet` 只压 stderr，`.error.hint` 在 JSON 信封里，照样会被你读到。技能侧一律显式
   `--tunnel off`——实测端点拒绝连接时退出码 3、`kind=TRANSPORT`、SSH 进程数前后不变；而 CLI 缺省
   `auto` 会在同样的失败上**自己 spawn 一条 SSH 转发到网关所在主机**，那是运维动作（`SKILL.md` §7）。

## 排障配方（按配额从低到高）

```bash
run tools -f json --keys-en --quiet --tunnel off     # 零配额：握手 + tools/list，验端点与 schema 指纹
run search "x" --dry-run --tunnel off                # 零出网：看将要发出的 arguments 里有没有 null 键
run doctor --tunnel off                              # 分层探活，含 1 次最小搜索（消耗 1 点配额）
```

顺序固定：先 `--dry-run` 确认本地面没问题，再 `tools` 确认链路没问题，最后才轮到 `doctor` / 真实搜索。
`tools` 的输出里 `schema指纹` 与内置副本不一致会打漂移告警——那意味着服务端参数增删过，
此时**别凭记忆写参数**，回去读 `run <命令> --help`。
